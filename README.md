# 信贷申请评分卡与审批策略分析

> **结论**：在 30,000 条信用卡客户数据上构建申请评分卡（AUC 0.769 / KS 0.408），
> 将审批通过率从 100% 收紧到 **77.4%**，坏账率从 **22.01% 降至 13.10%**——
> 即每 100 个原本会被批准的申请中，拒绝掉 22.6 个高风险客户，就能让坏账率下降近 9 个百分点。

---

## 1. 业务问题

消费信贷审批的核心权衡：**放宽通过率能做大业务量，坏账率随之上升。**

本项目回答的不是"能不能预测违约"（这个早有答案），而是：

> **在给定的风险容忍度下，审批阈值应该设在哪里？**

评分卡只是手段，**决策才是产出**。

---

## 2. 数据

| 项目 | 内容 |
|---|---|
| 来源 | [UCI Default of Credit Card Clients](https://archive.ics.uci.edu/dataset/350/default+of+credit+card+clients)（台湾某银行，2005） |
| 规模 | 30,000 条 × 25 列 |
| 坏账率 | 22.12%（6,636 / 30,000） |
| 切分 | 训练 21,000 / 测试 9,000（按 id 取模，可复现） |
| 标签 | `default payment next month`：下个月是否违约 |

**每个客户有 6 期历史行为的快照：**

| 字段组 | 含义 |
|---|---|
| `PAY_0, PAY_2..PAY_6` | 最近 6 期还款状态：-2 无消费 / -1 全额还款 / 0 循环信用 / 1..9 逾期月数 |
| `BILL_AMT1..6` | 各期账单金额 |
| `PAY_AMT1..6` | 各期实际还款金额 |
| `LIMIT_BAL` | 信用额度 |

**这正是"用行为预测行为"的落点**：模型输入全部是客户过去 6 期**已发生**的还款行为，
输出是下一期是否违约。没有任何未来信息。

---

## 3. 方法

### （1）行为特征构造

从 18 个原始行为字段构造 8 个可解释的行为指标：

| 特征 | 构造方式 | 业务含义 |
|---|---|---|
| `late_cnt` | 6 期中逾期期数 | 逾期频率 |
| `max_late` | 6 期最大逾期月数 | 最坏情况 |
| `late_cur` | 最近一期状态 | 当前紧迫程度 |
| `util_cur` / `util_avg` | 账单 / 额度 | 额度使用压力 |
| `util_trend` | (最近账单 − 最早账单) / 额度 | 负债是否在恶化 |
| `repay_ratio_cur` / `repay_ratio_avg` | 还款 / 账单 | 还款意愿与能力 |

### （2）标签与切分

标签直接取 `default payment next month`。

**切分说明**：该数据无日期字段，无法做严格的时间切分，本项目按 `id % 10` 做确定性切分
（70/30，可复现）。**这是本项目的主要局限之一**——真实业务必须用放款日期做时间切分，
否则会因同期宏观环境和审批政策产生虚高的样本外表现。

### （3）模型

- WOE 编码 + IV 筛选（IV > 0.02 保留）
- Logistic 回归作为评分卡本体
- HistGradientBoosting 作为对照
- 评分映射：PDO = 20，基准 odds 1:1 对应 600 分

### （4）策略阈值

对 0.00–1.00 的 101 个阈值做**网格扫描**（SQL `CROSS JOIN` 一次算完），
得到每条阈值下的通过率、坏账率、预期损失，画出权衡曲线。

## 4. 关键结果

### 4.1 变量区分度

| 变量 | IV | 解读 |
|---|---|---|
| `late_cur` | 0.874 | 最近一期是否逾期，信号极强 |
| `max_late` | 0.760 | 历史最坏逾期程度 |
| `late_cnt` | 0.687 | 逾期频率 |
| `pay_avg` | 0.185 | 平均还款额 |
| `limit_bal` | 0.172 | 额度（代理收入水平） |
| `repay_ratio_cur` | 0.139 | 当期还款比例 |

> IV > 0.5 通常被认为"过强"，需要警惕信息泄漏。这里 `late_cur` 之所以强，是因为
> "本月已逾期"对"下月是否违约"本身就是极强的先验——**这不是泄漏，但意味着模型
> 高度依赖单变量。见 4.3 的对照实验。**

### 4.2 模型对比

| 模型 | AUC（训练） | AUC（测试） | KS（测试） | 训练-测试差 |
|---|---|---|---|---|
| **Logistic 评分卡** | 0.7709 | **0.7693** | **0.4078** | **0.0016** |
| GBM (HistGradientBoosting) | 0.7984 | 0.7814 | 0.4256 | 0.0171 |

**结论：选 Logistic。**

GBM 的样本外 AUC 只比 Logistic 高 **0.012**（1.2 个百分点），但它的训练-测试差
是 Logistic 的 **10.7 倍**（0.0171 vs 0.0016）。也就是说，GBM 多出来的那点表现，
有相当部分来自对训练集的过拟合；而它同时失去了系数级的可解释性、增加了上线与
模型监控的成本、降低了监管接受度。

**在信贷场景里，0.012 的 AUC 不值得用这些去换。**

### 4.3 稳健性：去掉最强特征会怎样

| 模型 | 全特征 AUC | 去掉 `late_cur` | 变化 |
|---|---|---|---|
| Logistic | 0.7693 | 0.7574 | −0.012 |
| GBM | 0.7814 | 0.7683 | −0.013 |

去掉最强的单变量后，AUC 只掉 1.2 个百分点。**说明模型不是单变量模型**，
其余行为特征（历史逾期次数、额度使用率、还款比例）有独立的解释力。
如果掉 5 个点以上，就要怀疑模型其实只是在用"本月是否已逾期"这一个信号。

### 4.4 策略阈值

| 方案 | 阈值 | 通过率 | 坏账率 | 相对基准 |
|---|---|---|---|---|
| 全放行（基准） | 1.00 | 100% | 22.01% | — |
| **建议阈值** | **0.28** | **77.4%** | **13.10%** | 坏账 −8.9pct |
| 更严 | 0.20 | ≈65% | ≈11% | 坏账 −11pct |

权衡曲线见 `reports/tradeoff.png`。

**建议**：把审批阈值设在 `pd_hat = 0.28`。此时保留 77.4% 的业务量，
坏账率从 22.01% 降到 13.10%——**牺牲 22.6% 的通过量，换来近 9 个百分点的坏账改善**，
在消费信贷里这是非常划算的交易。

具体停在哪里取决于机构的风险偏好和资金成本。如果不良容忍度更低，可以继续向左收紧，
但通过率会下降得更快（曲线在左侧变陡）。

---

## 5. 局限与后续

1. **无法做时间切分**——数据没有日期字段，用了 id 取模切分。真实业务应当用放款日期。
2. **拒绝推断缺失**——模型只在已放款客户上训练，被拒客户的特征分布不可见，
   上线后可能出现样本选择偏差。
3. **样本较早**（2005 年台湾市场），外推到当前大陆客群需谨慎。
4. **未建模额度决策**——只决定"批不批"，没决定"给多少"。后续可做额度与定价的联合优化。

## 6. 目录结构

```
.
├── README.md
├── requirements.txt
├── sql/
│   ├── 01_clean.sql       行为特征构造 + 切分（流水线执行）
│   ├── 02_eda.sql         分客群违约率、单调性检查（参考用查询集）
│   └── 03_strategy.sql    阈值网格扫描（流水线执行，核心 SQL）
├── src/
│   ├── load_raw.py        原始数据 → parquet
│   └── pipeline.py        端到端流程
├── data/                  数据（原始 CSV 入库，parquet 不入库）
└── reports/
    ├── strategy_report.md 分析报告
    ├── tradeoff.png       通过率–坏账率权衡曲线
    ├── summary.txt        关键数字
    ├── iv_table.csv       变量 IV 排序
    ├── model_compare.csv  模型对比
    └── threshold_sweep.csv 全阈值扫描结果
```

> **关于 `02_eda.sql`**：这个文件是给人看的参考查询集，**流水线不会执行它**。
> `pipeline.py` 的 EDA 步骤用的是内联 SQL 字符串（因为需要逐条打印结果，
> 而不是落盘）。它里面的查询都可以直接运行，可用于单独复现各张 EDA 表。

## 7. 复现

```bash
# 环境：直接用系统 Python 3.13（依赖已装好，无需 venv）
python src\pipeline.py
```

数据文件放在 `data/credit-card-clients.csv`。
若缺失，从 [UCI](https://archive.ics.uci.edu/dataset/350/default+of+credit+card+clients)
或 GitHub 镜像下载。

依赖：duckdb、pandas、numpy、scikit-learn、matplotlib（无需 pyarrow）。
